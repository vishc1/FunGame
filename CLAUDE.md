# FriendGame

Browser party games for friends on a call. Node + Express + Socket.IO server, vanilla canvas client. `npm start` → http://localhost:3000.

## Layout
- `server.js` — rooms (4-letter codes), lobby, results, 30 Hz tick loop. Loads every `server/games/*.js`.
- `server/games/<id>.js` — one server module per game. Exports `{ id, name, tagline, min, max, controls, create(api) }`.
  `create(api)` returns `{ onInput(pid, msg), tick(dt), onLeave(pid), onJoin?(pid), destroy() }`.
  `api`: `players()`, `player(id)`, `emit(ev, data)` (room), `to(pid, ev, data)`, `after(ms, fn)`, `every(ms, fn)`, `clear(t)`, `end(pointsById, summary)`, `memory` (persists across games in a room).
  Games send `g:state` snapshots (≤30 Hz) and `g:event` one-offs. Call `api.end({pid: points}, 'summary')` to finish.
- `public/app.js` — client framework. `registerGame(id, (G) => ({ state(s), event(e), render(dt), key(k, down), mouse(kind, x, y), destroy() }))`.
  `G`: `ctx`, `W=900`, `H=600`, `me` (socket id), `players`, `player(id)`, `keys` (Set of held keys, lowercase), `mouse {x,y,down}`, `send(msg)`, `ui` (DOM overlay), `panel(html)`, `clearUI()`, `text()`, `circle()`, `nameTag()`, `timer()`, `clear()`.
- `public/games/<id>.js` — client module, included from `public/index.html`.
- `server/data/` — word lists and trivia.
- `server/bots.js` — test-mode bots. One brain per game (`BRAINS[gameId]`) that turns the latest state snapshot into input messages. Add a brain when adding a game.
- `public/vendor/` — vendored Three.js (ESM, via import map) and GLTFLoader; exposed as `window.THREE` / `window.GLTFLoader`.
- `public/models/` — optional `.glb` overrides for Meme Karts (see `3d.md`); `/models/list` lists them.
- `tools/` — dev checks. Run these after any change; all must be clean:
  - `node tools/fullrun.js [gameId]` — every game played to the end on a virtual clock, 8 scenarios each (min/4/8 players, junk input, leaves, joins). Fast.
  - `node tools/lifecycle.js` — room lifecycle and malformed messages against a real server process.
  - `node tools/kartsim.js <mapId>` — Meme Karts match where bots use all items.
  - `node tools/solo.js <gameId> [secs] [shot times]` — headless Chromium through Test mode (bots), screenshots in `tools/shots/`.
  - `node tools/multi.js <gameId> [secs] [shots] [players] [mapId]` — N real browser clients joining by code. Run WebGL games one at a time (software GL is slow). `QS='?bloom=1' MAP=neon node tools/solo.js memekarts` forces bloom on and picks a map.
  - `node tools/mapcheck.js` — Meme Karts map layouts: overlaps, bounds, reachability.
  - `node tools/blasters-hit.js`, `node tools/blasters-shots.js` — shooter: a real browser's shot must register; captures the main screens.
  - `node tools/mp.js` — two separate browsers in one room for both primary games: each sees the other move, shots land. `node tools/home.js` — home page and lobby game switch. `node tools/blasters-rules.js`, `node tools/blasters-map-check.js` — shooter rules and map physics without a browser.
  - `node tools/refresh.js [gameId]` — real page refresh in the lobby and mid-game, plus the Leave button.
  - `node tools/kart-items-check.js` — every Meme Karts item fired at placed karts, asserting the logical outcome (hits, homing, bounces, steals, immunities, timers). `node tools/blasters-items-check.js` — every shooter pickup, power-up and hitscan blaster rule on both maps. Run both after touching items. Power-ups: `POWERS` in the shared file; `rare: true` ones come up through `rollPower()` (25%): `inf` (no ammo use, server), `vamp` (heal on hit, server), `moon` (`body.grav` in the shared physics, set by the client and the bots), `bighead` (client-only: bigger `headR` in `rayPlayer` and scaled heads), `shadow` (server: hits do 999; client: figure hidden from enemies; bots ignore them).
  - `node tools/mobile.js` — the site on an emulated iPhone. Both main games draw a minimap in the top-left of the HUD (you as a marker, players, hazards) with the match numbers under it; the shooter shows enemies only when close or just fired (`recentShot`).  (touch, no pointer lock): home and lobby fit, Meme Karts d-pad, Toy Box Blasters joystick / look drag / fire button. Touch controls: `.kart-touch-controls` in `public/games/memekarts.js` (Codex's), `.bl-touch` built by `buildTouch()` in `public/games/blasters.js` (shown only under `pointer:coarse`; the shooter runs soft-locked on touch). `#rotateHint` asks for landscape.
  - `node tools/gfx.js` — the graphics setting (`public/gfx.js`: Low/Medium/High in `localStorage.fg_gfx`, `?gfx=` override; games read `window.FG_GFX.cfg()` and apply live on the `fg-gfx` event via `T.applyGfx()`). `node tools/zfight.js` — walks the rendered scene of every map for flush same-facing surfaces (z-fighting) and for scenery inside the play area. `node tools/views.js` photographs every map from three fixed cameras (`window.__camOverride`) for a visual pass. Timing-based browser drives (`kart-ramp.js`) fail when several run at once; run them one at a time.
  - Toy Box Blasters rounds: 3 minutes, then the winner for `NEXT_IN` (6 s) and `newRound()` on the same map unless the lobby option is One match (`api.memory.blastersRounds === 'one'`, which `tools/fullrun.js` uses). Figure, skin and starter blaster are picked BEFORE a game, on the home page (3D preview) and in the lobby (`public/toy-picker.js`, localStorage `tbb_char`/`tbb_skin`/`tbb_lo`, read by the game at start); the in-game L menu is settings only. `node tools/toy.js` checks it. The home page gallery images come from `node tools/gallery.js` (`public/img/shots/`). The HUD shows the held blaster as a picture rendered from its model (`T.icon(w)`).
  - `node tools/away.js` — Esc in both games: 2 s countdown (click or key cancels), then an away screen; the player sends `{type:'away', on}`, the server keeps their seat and score and takes them out of the world (`p.away` / `k.away`, snapshot `aw`; karts are parked at -5000), Back respawns them in the same match. `node tools/ramp-sides.js` (kart ramp sides are walls) and `node tools/pad-landings.js` (no pad flight in either game passes through a wall, deck or box).
  - `node tools/items.js [mapId]`, `node tools/playnow.js`, `node tools/shapes.js`, `node tools/glbinfo.js <file.glb>`.

## Conventions
- Server is authoritative for all game state; clients only render snapshots and send intents.
- Canvas is a fixed 900×600 logical space, CSS-scaled. Mouse coords arrive already in canvas space.
- Keep state snapshots small: round numbers, send only what the renderer needs.
- Reference implementation: `server/games/sumo.js` + `public/games/sumo.js`.
- Toy Box Blasters (`blasters`) is a first-person shooter and the one game that is NOT fully server-authoritative: each client simulates its own movement with the shared physics and reports it (`{type:'p'}`), and reports its own hitscan hits (`{type:'fire', hits}`); the server enforces fire rate, ammo, range, damage, pickups, rockets, scoring. Maps, physics, rays and the weapon table live in `public/games/blasters.shared.js`. Three maps (`MAPS`: `fort` Fort Cardboard, `towers` Block Towers, `cove` Pirate Cove), built by `build(id, ...)`; every physics/ray function takes the map as its LAST argument (`stepPlayer(p, inp, dt, mul, map)`, `overlap(x, y, z, map)`, `rayMap(..., max, map)`, `los(..., map)`), defaulting to `MAP` (fort). The room's map comes from `api.memory.blastersMap` (lobby `pickMap`), is sent in every snapshot as `s.map`, and client/bots read it from there. Team mode: lobby `pickMode` (`ffa`/`teams`) -> `api.memory.blastersMode`; snapshot `tm`, per-player `tm`, team tags `tk`; no friendly fire; Red spawns north (z<0), Blue south; max 12 players. `tools/solo.js`/`multi.js`/`blasters-shots.js` take `MAP=` and `MODE=teams`. Codex's arena model is `fps_arena.glb` (fort only) or `fps_arena_<map>.glb` (UMD: `require` on the server and bots, `window.BLASTERS` in the browser). Bots run the same physics in `server/bots.js`. Models: `fps_*.glb` in `public/models/` (figures fitted by their `head_core` mesh, blasters used at authored size with the grip-bottom origin, `fps_arena.glb` replaces the plain floor and boxes). Test hooks `__bl` / `__blAim` exist only with `?bltest=1`. The first-person blaster is a child of the camera on render layer 1, drawn in a second pass (Codex's `art/blasters/check-assets.mjs` relies on it being under the camera). The map also has `ramps` (true slopes; a ramp ending in mid-air is a launch ramp), `teles` (teleporter pairs) and `train` (server-simulated hazard along z = 0); skins (`sk`) restyle each figure's `Paint` material. `node tools/blasters-map-check.js` tests the map and movement physics without a browser. Graphics brief: `fps3d.md`; `node tools/blasters-map.js` exports the collision boxes for artists.
- Meme Karts maps are data in `public/memekarts-maps.js` (per-map `w`/`h`, obstacles, boxes, spawns, pads, portals, zones, movers). `node tools/mapcheck.js` validates them. The renderer uses `OX`/`OZ` world offsets, never literal 450/300.
- Games listed in `FULL_WINDOW` in `public/app.js` fill the whole window and manage the canvas size themselves.
- The site revolves around two primary games, Meme Karts and Toy Box Blasters. `public/home.js` drives the home page's two-game picker (`window.selectedGame`); the lobby has the same switch (`#gameSwitch`); the other 13 games live under "More games". `node tools/home.js` checks all of it.
- Meme Karts has real height: `decks` (raised blocks, `DECK_Z` = 48 high, or `z: TOWER_Z` = 100 for a second tier stacked on a deck) and `ramps` (slopes with optional `z0`/`z1`; a tower's second ramp runs 48 -> 100 on top of the first deck). Every map has one sky tower (two-stage climb to a summit box). A wall is a rise steeper than `GRADE` (0.72 per unit travelled), so taller ramps climb at any speed. `maps.deckZ(d)` / `maps.rampZ(r)` give heights; `art/check-environment.mjs` reads them too. All of it lives in `public/memekarts-maps.js`, with `maps.surface(map, x, y)` as the one ground-height function used by server, bots and renderer. Karts and items carry `el` (elevation); a drop over 10 is a fall, and things only interact on the same level. `node tools/kart-height.js` (rules) and `node tools/kart-ramp.js <map>` (browser) check it. Jump pads still launch karts through the air. The Cream pie (`pie`) is the one held item: the client charges while SPACE/mouse is held (`trigger()`), sends `{type:'fire', charge}` on release, and `T.aim()` draws the arc; the server item gets `fire(g, k, charge)`. Spawns in both games pick randomly among the farthest spots. Blasters mechanics beyond shooting: crouch/slide (shared physics), aim-down-sights (per-weapon `ads`), bursts, lobbed projectiles (`gravity`), `MELEE` foam sword. `node tools/blasters-rules.js` checks the server rules.
- Meme Karts and Toy Box Blasters are the 3D games. For Meme Karts: the server sim is still flat 900×600; `public/games/memekarts.js` renders it with Three.js on a WebGL canvas placed behind the framework's 2D canvas, which it uses for the HUD.
- After changing a game, run `node tools/fullrun.js <gameId>` and `node tools/solo.js <gameId>`, and look at the screenshots; zero failures and zero console errors is the bar.
- Clients are untrusted: validate every input field (`Number.isFinite`, known ids). Socket handlers in `server.js` are registered through the `on()` wrapper so a bad payload cannot crash the server; game timers and join/leave hooks run through `room.guard()`.
- Player ids are stable (`u…`), not socket ids. A disconnected player keeps their seat for `REJOIN_GRACE_MS` (20 s) and the browser reclaims it with the id + secret key in `sessionStorage` (`rejoin`). A game that sends one-time setup by event (a map, a secret word) must also implement `onRejoin(pid)` to resend it. Client code uses `G.me`, never `socket.id`.
- A game must end itself when fewer than two players remain (`onLeave`), not leave one person alone until the clock runs out.
- Two transports, one hub. `server/hub.js` holds all room/lobby/bot/game-loop logic behind a Socket.IO-shaped `io`. `server.js` runs it with real Socket.IO (local play, any always-on host). `server/host-worker.js` runs the same hub in a Web Worker inside the room creator's browser, and `public/p2p.js` gives the client a socket-like object over WebRTC (PeerJS) so guests connect straight to the host. `public/app.js` picks peer-to-peer when `window.FG_P2P` is true (`public/config.js`, written by the build; `?p2p=1`/`?p2p=0` overrides).
- Hosting: https://friendgame.vercel.app is a STATIC Vercel deployment (`vercel.json`: build `npm run build`, output `public/`, no functions) in peer-to-peer mode. Vercel cannot hold a game server (connections cut at 300 s, no shared memory between instances), which is why. Deploy with `npx vercel@latest deploy --prod --yes`; retry once on a spurious "Not authorized". `server/build-manifest.js` generates `server/registry.js`, the model lists, `public/host-worker.js` (esbuild bundle, git-ignored), `public/config.js` and the vendored client libraries. In peer-to-peer mode the room ends if the host closes or refreshes their tab. Tests: `P2P=1 node tools/mp.js`, `node tools/p2p.js`, and `BASE_URL=https://friendgame.vercel.app node tools/mp.js|p2p.js|p2p-long.js` for the live site.
- Browser test tools use Playwright's window-less `chrome-headless-shell` with `--use-angle=metal` (real GPU, ~120 fps, no Dock icons). Peer-to-peer tests also pass `--disable-features=WebRtcHideLocalIpsWithMdns`: two browsers on one Mac can only reach each other over WebRTC when mDNS resolution works, and on 2026-10-09 it stopped working on this Mac (a bare loopback data channel stuck in ICE 'checking' with `.local` candidates, instant with real IPs). Real players on different machines are unaffected. If `P2P=1 node tools/mp.js` reports 'Could not reach the room', suspect the Mac before the game. Software rendering ran at ~6 fps and made timing tests fail. Codex's own checks under `art/` launch the real Google Chrome, which the user notices; avoid running those more than needed.
- Another agent (Codex) also edits this folder: check `stat` times before large edits and keep edits small and anchored. Never put a `//` comment in the middle of a long one-line statement.
